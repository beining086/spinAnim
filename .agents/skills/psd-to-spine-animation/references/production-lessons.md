# 制作复盘与检查表

案例素材来自用户提供的 `s1.psd`。后续参考 `sn_s1.skel` 与 `sn_s1.atlas`，复盘范围包括最早的转向版本、华丽金矿版、原地行驶循环和性能精简版。

| 问题 | 原因或信号 | 复用的处理方式 |
| --- | --- | --- |
| PSD 看起来像一张矿车平面图 | 外层显示的是智能对象的合成预览 | PSD 解析时递归列出可见层、组和智能对象；打开内嵌 `rerjj (4).psb`，应用变换和蒙版后取车斗、把手、底架、车轮、宝石和金矿 |
| 转向开裂、内壁从侧面伸出 | 独立贴片使用不同角度、缩放或变形，重叠处没有共用位置 | 在同一空间里决定视角，让接缝两边共享投影。只用小范围网格修正硬边。出现露边时先查车沿、底架和内壁的世界顶点及绘制顺序 |
| 转向生硬或车轮被压扁 | 仅横向压缩会让车头像橡皮形变；过强的轮面压缩会吃掉轮辐 | 用前近后远、轮轴相对位置和车体轮廓共同建立透视；为轮面设置合理的最窄外观。让同轴的近远侧轮在同一方向呈现，补足底板遮挡 |
| 转轮时轴帽绕圈 | 带高光的鼓包轴帽和轮辐一起在斜视贴图平面旋转 | 将轴帽独立固定；绕轮轴旋转归一化的轮辐，再投回画好的椭圆。用局部角向拖影覆盖轮辐，避免把整个车轮做方向性平移模糊 |
| 玩起来一直模糊，首尾和静态图对不上 | 旋转和模糊自首帧就生效，或车身、宝石、光效未一起归位 | 减速阶段让速度、模糊透明度、车身姿势和发光一起回到起点。先验证原图拆件能否重建静态图。要求像素相等且有差异时，启用独立静态参考附件并在同姿势下切换。把新增图集页列入运行依赖 |
| 想要中奖感，但金币和冲击波偏离美术需求 | 奖励符号和特效样式没有沿用反馈 | 这个案例使用有棱角的飞散金矿、各色宝石、材质内扫光、星芒和柔和背光。金币、线状冲击波和环形拖线在反馈后去掉。起伏的最大幅度、颗粒发射时机和亮度峰值用一个主拍组织 |
| 参数量大，用户难以调整帧 | 逐帧变形记录纯旋转，静态区域依然保留细密网格 | 把纯轮辐转动换成旋转骨骼，矩形且无形变的刚性部件用 Region。减少常值与误差可控的插值键；在撞击接触、换图、首尾和高光峰值保留必要的键 |
| 应用里打开文件但下载失败 | 云文件预览路径与本地下载入口不同 | 交付前解压验证。如果用户授权上传仓库，回读提交后的 ZIP 和预览，对比 SHA 或字节。给出可访问的直链和预览入口 |

## 本例的精简结果

- 原地行驶的优化版由 11,595 个原始关键帧降到 3,746 个。Spine JSON 从 1,699,914 字节降到 170,406 字节，图集和单图源码属于另外的体积。
- 车轮的后绑定过程将椭圆局部坐标转成圆形坐标，通过子骨旋转再投回原画。清晰轮面和模糊轮面共用该旋转骨，轴帽单独停留在轮轴座上。该改动去掉了 6 条逐帧轮面网格变形轨。
- 对比使用相同的 30 fps 时间点和 Spine 3.8 Runtime。首尾与 PSD 静态图逐像素相等。活动段有受控的插值差异，不能把此段描述成逐帧完全一致。继续减键时，以脉冲、位移、角度和视觉误差分别限幅。

## 配置与抽查

1. **静态**。用正确的缩放和原始画布导出静态图。第 0 和末帧对比原图及彼此；预览采用有损压缩时也要单独确认静态帧保真。不要将关键帧数量当成视频帧数。
2. **部件**。最大前冲或转角暂停检查车头、车尾、车沿、轮轴、底架和把手。至少检查半帧时间采样，确认插值没有开缝、翻面、突然变扁、遮挡跳层和越界。
3. **车轮**。裁出轮区对比 0、约 1/4 周、1/2 周、最慢与最快帧。轴帽局部中心固定，模糊与速度匹配，轮轴投影和接触点合理。持续滚动的循环检查轴帽相位与清晰轮面在首尾的过渡。
4. **特效**。检查矿石与宝石是否从斗内发出，扫光有没有越过轮廓，重要部位有没有被高光覆盖。终点关闭临时高光或碎片，并核对插槽颜色和绘制顺序。
5. **导出**。核对 JSON 或二进制版本、每张 atlas page、PMA、附件裁剪旋转信息和可编辑图片路径。记录兼容运行时、动画名、时长、播放或制作采样率、精简前后键数。说明哪些检查在 Runtime 做过，哪些还需用编辑器或游戏引擎验证。
