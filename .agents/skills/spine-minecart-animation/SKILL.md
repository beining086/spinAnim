# Spine 矿车动画

先确认交付版本、时长、参考静态图和动作目标。沿用用户指定的画布、风格、取舍和上传位置。延续本案例时使用 Spine 3.8.99、1.5 秒循环和 30 fps 的制作时间轴，按第 0 帧与第 45 帧检查闭合。关键帧精简与播放采样率分别处理。

## 分析源素材

1. 展开 PSD 图层组和智能对象，优先取内嵌 PSB 的原始拆件。记录父 PSD 中智能对象的变换、蒙版、透明度、图层顺序和静态合成图。
2. 收到 `.skel` 时先读出版本，使用同版本系列的运行时解码。用 `.atlas` 核对页名、裁剪、偏移及旋转打包。若图集 PNG 缺失，仍可检查动画数据和顶点位置，把像素和完整视觉结论标为待验证。
3. 检查主骨骼、轮轴父子关系、静态槽和运动槽各自的轨道。分别统计附件切换、骨骼插值、网格变形和颜色关键帧。查询首尾和动作峰值的可见附件、颜色及世界顶点。案例分析见 [sn_s1 解析](references/sn_s1-analysis.md)。
4. Spine 3.8 二进制分析可用随附脚本。提供官方 3.8 `spine-webgl.js` 的可信本地副本，再运行：

   ```bash
   node scripts/inspect-spine38.cjs /path/to/spine-webgl.js /path/to/file.skel /path/to/file.atlas
   ```

## 建立动画

- **原地行驶**。车斗外壁、内壁、把手和底架共享车身主骨骼。主骨骼只做上下起伏、轻微摆动或等比缩放，参考点保持原地。用轮辐和沿地面向后散开的碎屑交代方向。先关闭特效看车身轮廓和轮轴连接。
- **透视转向**。先确定正视程度和最大转角。让接缝两侧共用控制骨或共享投影，在鼻端、车沿、内壁、底架和把手的搭接处放控制点。验证极值和中间插值。适度变化前后体积，检查轮面宽度、同轴的近远侧轮和远侧轮与底板的遮挡。根据视角变化选择少量网格控制点或配套视角素材。
- **车轮**。把胎壁、轮辐、轴帽拆层。轴帽固定在车轴座，轮辐围绕固定中心滚动。倾斜轮面可先把椭圆归一化为圆形坐标，在子骨旋转，再由父骨投回椭圆。另一做法是同轴对齐的清晰轮面、少量循环附件和独立旋转轮层。清晰层与模糊层随速度交接。
- **载荷与中奖节奏**。奖赏重拍安排在较大的路面冲击附近，先让车身起伏，再让金矿和宝石错峰弹起与落回。把独立高光绑在对应载荷骨骼上，并用车斗前沿遮挡回落部分。发光用加法贴图与透明度脉冲，扫光沿材质移动并限制在矿石或宝石轮廓内。用矿石碎片、星芒、短促的背光丰满主拍。根据用户反馈选择碎片、金币、光环和线条类效果。
- **静态接点**。先让活动层自然回到静态姿势，复位轮辐相位，关闭拖影和特效。若原始 PSD 与拆件合成有微小像素差且用户要求逐像素一致，可在已归位的首尾使用完整参考图附件，进入动势前切回分层角色。把该附件设为独立槽，记录静态页及其编辑用途。

## 精简与交付

每次精简以原动画渲染为基线。先用原生旋转骨骼替代纯旋转的逐帧网格数据，将始终保持矩形 UV 的刚性部件改用 Region，再考虑删掉重复值或拟合连续曲线。保留接缝压力最大的区间、轮面切换、模糊交接、击中峰值及首尾的原关键帧。分段保留足够的旋转关键帧，以免运行时按最短弧反转。

用目标版本 Runtime 检查 0 帧、终帧、最大转角、最高和最低起伏点、清晰与模糊换层、远侧轮和接缝。额外在半帧或更密的时间点检查是否越界、开缝或有轮轴漂移。分别报告时长、采样率、实际关键帧数量和精简结果。逐像素校验需要原始静态图和实际渲染像素。骨骼与可见槽一致只能证明数据层面匹配。

交付可编辑 JSON、单图素材、配套图集页、预览和导入说明。区分编辑器导入检查与 Runtime 测试。按用户授权的目的地交付并回读文件。遇到问题按 [制作复盘与检查表](references/production-lessons.md) 定位。
